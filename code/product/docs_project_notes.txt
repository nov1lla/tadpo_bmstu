# Project Quick Notes (keep this in sync)

## Vision & Scope
- Проект: система визуализации ходов в игре (шашки/шахматы) с AI-партнером и анимацией перемещения на виртуальной доске.
  * Правило “обязательное взятие”: если на доске есть возможное взятие для текущего игрока — он обязан бить.
  * Правило “обязательное продолжение взятия”: если после взятия у той же фигуры есть ещё взятие — ход обязан продолжаться цепочкой до исчерпания взятий.
  * Король (king) ходит и бьет только на 1/2 клетки по диагонали в любую сторону (без “дальних” ходов).

## Архитектурные уровни
- **Domain**: структуры `User`, `Game`, `Move`, `BoardState`, `Position`, `Animation`, константы (например `domain.DefaultBoardSize`). Инварианты внутри конструкторов (`NewMove`, `Game.Finish`).
- **Use Cases**:
  - `UserUseCase`: `Create`, `Get`, `UpdateFields`.
    * `Create` теперь сам генерирует `UserID`, рейтинг/серия побед стартуют с 0.
  - `GameUseCase`: `New`, `ProcessMove`, `FinishGame`, `GenerateHistory`, `GetChessboard`, `UpdateBoardState`.
    * `New` и `ProcessMove` генерируют идентификаторы партий/ходов и считают номера ходов.
  - `MoveUseCase`: `AddUserMove`, `GetOpponentMove`.
    * Формируют номера ходов, обновляют статус игры `pending → in_progress`.
    * Для ответов ИИ включено логирование (std log) и fallback-построение траектории, если LLM прислал промежуточные клетки жертвы.
  - `AnimationUseCase`: `AnimateMove` (обработка блокирующих фигур, вывоз жертвы).
- **Ports**:
  - Репозитории (`internal/port/repo`): `UserRepository`, `GameRepository`, `MoveRepository`.
  - `BoardStateReader` (для анимации).
  - `OpponentMoveProvider` (OpenAI / mock).
  - `IDGenerator` — источник уникальных идентификаторов (реализация на UUID).
- **Infrastructure**:
  - PostgreSQL (реализация в `internal/repository/postgres`, транзакции на `Save`/`UpdateBoardState`).
  - Локальное JSON-хранилище (`internal/repository/localjson`) — репозитории поверх файлов, включаются через конфиг `DATA_SOURCE` и не требуют БД.
  - OpenAI клиент (`internal/adapter/openai`) — требует явного `model`/`base URL` из конфига, возвращает `domain.Move`, различает `APIError`, `ErrEmptyResponse`, `ErrMalformedJSON`.
    * Промпт жёстко описывает правила (цвет ИИ, индексация, формат path с landing squares).
  - Плагины (`plugins/data`, `plugins/business`) позволяют собрать приложение динамически через `buildmode=plugin`; интерфейсы объявлены в `internal/component`.
  - DI (`internal/app`) — строит приложение по конфигу (`internal/config`).
  - Генератор идентификаторов (`internal/service/idgen`) — `UUIDGenerator`, внедряется во все use case.
- **Config** (`internal/config/config.go`): читает `POSTGRES_DSN`, `OPENAI_API_KEY`, `OPENAI_MODEL`, `OPENAI_BASE_URL`, `HTTP_TIMEOUT` (дефолт 10s).

## Анимация захвата (физическая доска)
- Для отображения захвата: сначала “сбрасываем” побитую шашку с доски по неиграбельным клеткам в сторону её игрока, затем передвигаем атакующую шашку на клетку побитой, и только потом — на клетку приземления.
- Если за ход несколько взятий, повторяем последовательность по каждому взятию.
- На бэке есть usecase, который принимает ход + снимок доски и возвращает список шагов перемещений (для пошагового воспроизведения на фронте).

## Полезные сценарии запуска
- Все тесты (verbose, без кеша):
  `POSTGRES_DSN=postgres://postgres:password@localhost:5432/ppo_cource?sslmode=disable go test ./... -v -count=1`
- Только репозитории: `go test ./internal/repository/postgres -v -count=1`
- Интеграция + live OpenAI:
  `RUN_OPENAI_LIVE_TEST=1 OPENAI_API_KEY=... OPENAI_MODEL=gpt-4o-mini go test ./internal/integration -run TestLiveOpenAIIntegration -v -count=1`
- Сборка через плагины:
  `go build -tags plugin -buildmode=plugin -o build/data.so ./plugins/data`
  `go build -tags plugin -buildmode=plugin -o build/business.so ./plugins/business`
  `go build -o build/techui_modular ./cmd/techui_modular`
  Запуск: `DATA_PLUGIN_PATH=build/data.so BUSINESS_PLUGIN_PATH=build/business.so DATA_SOURCE=./config/data_postgres.json ./build/techui_modular`
  Для локального режима: `DATA_SOURCE=./config/data_local.json`.
