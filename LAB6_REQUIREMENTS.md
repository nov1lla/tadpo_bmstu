# Лабораторная работа №6 — статический анализ, code style и pre-commit

Цель ЛР: добавить в проект автоматические проверки качества кода, которые **ловят проблемы до запуска тестов**:
- метрики сложности (цикломатическая и Холстеда),
- code style (для Go — `gofmt`, линтеры),
- запуск перед каждым коммитом (pre-commit hook),
- и запуск в CI/CD **до** тестов.

Ниже — разбор каждого пункта задания/требований: что означает, где реализовано в проекте и как продемонстрировать.

---

## Задание

### 1) Метрики сложности: Cyclomatic + Halstead

**Что это значит**
- **Цикломатическая сложность (Cyclomatic complexity)** — грубо говоря, «сколько ветвлений» в функции (`if/switch/for/...` и т.п.). Чем выше — тем тяжелее тестировать и поддерживать.
- **Сложность по Холстеду (Halstead Complexity)** — метрики на основе количества операторов/операндов в коде, дают оценку “объёма/усилия” для понимания функции.

**Где реализовано**
- **Cyclomatic**: `golangci-lint` + линтер `gocyclo` с порогом 10:
  - `.golangci.yml`
  - `code/product/run_static_checks.sh` (запуск `golangci-lint` для каждого Go-модуля)
- **Halstead**: небольшой инструмент на Go (чтобы не тащить внешние бинарники и чтобы одинаково работало локально/в CI):
  - `tools/halstead/go.mod`
  - `tools/halstead/main.go`
  - результат сохраняется в `code/product/test-report/static/halstead.json`

**Как продемонстрировать**
1) Запустить проверки:
   - `make tools`
   - `make lint`
2) Открыть отчёт по Холстеду:
   - `code/product/test-report/static/halstead.json`
3) Проверить ограничение по цикломатике:
   - временно добавь сложную функцию с кучей `if` (или искусственно усложни существующую),
   - запусти `make lint` — линтер упадёт на `gocyclo`.

### 2) Code style (линтеры/проверка типов)

**Что это значит**
- Для Go «базовый стиль» — `gofmt`.
- Дополнительно полезны линтеры (часть из них уже внутри `golangci-lint`).

**Где реализовано**
- `gofmt` проверяется на всех `.go` файлах в `code/`:
  - `code/product/run_static_checks.sh` (секция `gofmt (check)`)
- `golangci-lint` запускается по модулям:
  - `code/components/business`
  - `code/components/data`
  - `code/sdk`
  - `code/apps/webapp`

**Как продемонстрировать**
1) Сделай форматирование неправильным (например, убери пробелы/переносы).
2) Запусти `make lint` — получишь список файлов, которые требуют `gofmt`.

---

### 3) Запуск перед каждым коммитом (pre-commit), запрет коммита при fail

**Что это значит**
- Git позволяет запускать hook `pre-commit` перед созданием коммита.
- Если hook возвращает ненулевой код — коммит прерывается.
- Исключение: `git commit --no-verify` (обход hook — по условию разрешён).

**Где реализовано**
- Hook лежит в репозитории:
  - `.githooks/pre-commit`
- Установка hook-path:
  - `make hooks-install` (делает `git config core.hooksPath .githooks`)

**Как продемонстрировать**
1) Установить hooks:
   - `make hooks-install`
2) Поломать стиль/сложность и попробовать коммит:
   - `git commit -am "test"` → коммит должен быть остановлен (hook запустит `make lint`).
3) Показать обход:
   - `git commit -am "test" --no-verify` → коммит пройдёт.

---

### 4) Запуск этих проверок в CI/CD до тестов

**Что это значит**
- В пайплайне проверки должны идти **раньше тестов**.
- Если проверки падают — тесты не запускаются.

**Где реализовано**
- GitHub Actions workflow:
  - `.github/workflows/lab6.yml`
- Порядок:
  1) `make tools`
  2) `make lint`
  3) `docker compose ...` (запуск тестов как в ЛР2)
  4) upload артефактов `code/product/test-report` (включая `static/halstead.json`)

**Как продемонстрировать**
1) Запушить ветку `lab_06`.
2) Открыть вкладку Actions → workflow `lab-06-static-analysis`.
3) Убедиться, что step `Static checks ...` выполняется до `Run tests in Docker`.

## Требования

### (1) Максимальная цикломатическая сложность = 10 и фиксы в кодовой базе

**Где реализовано**
- `.golangci.yml` → `linters-settings.gocyclo.min-complexity: 10`
- Кодовая база отрефакторена так, чтобы проходить порог без `//nolint:gocyclo`.

**Как проверить**
- `make lint` должен проходить.

---

### (2) Code style в соответствии с языком

**Где реализовано**
- Для Go: `gofmt` + `golangci-lint`.

**Как проверить**
- `make lint` падает на неотформатированных файлах и просит прогнать `gofmt`.

---

## Полезные команды

- Установить инструменты: `make tools`
- Запустить все статические проверки: `make lint`
- Установить pre-commit hooks: `make hooks-install`
- Запустить юнит-тесты: `make test-unit`
- Запустить «как в CI» (Docker): `make test-ci-docker`
